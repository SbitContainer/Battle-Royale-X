# APK publication safety

`Publish-GitHubApk.ps1` accepts the immutable candidate generated by `PrototypeApkReleaseBuild`, plus the exact approved Editor log. It does not build/install, change privacy, replace releases/assets/tags or change signing settings.

Offline preparation (no credential lookup or network):

```powershell
.\Tools\Release\Publish-GitHubApk.ps1 -ReleaseDirectory '.\Builds\Releases\12' -TestsLog '.\Logs\approved-matrix.log'
```

Only add `-Publish` after human authorization for the exact candidate and public repository `SbitContainer/Battle-Royale-X`. Authentication uses existing `GH_TOKEN` or noninteractive Git Credential Manager, only in memory. Never paste secrets into logs, scripts or release notes. Tools require aapt/apksigner and Unity's OpenJDK; paths can be supplied explicitly.

Gates: BUILT_NOT_PUBLISHED, code > 11, correct package, zero build errors, matching APK/log/source-inventory hashes, completed combat gate, at least 48 structural visual passes, internal APK identity and valid existing prototype certificate. No new code automatically proves the Android touchscreen or performance.

Publication creates a unique draft `android-lab-CODE`, uploads `BattleRoyaleX-CODE.apk`, `brx-update.json` and sanitized `source-inputs.json`, verifies downloaded bytes, then publishes. Anonymous public downloads must also match before `publication.json` records PUBLISHED_VERIFIED. The original builder manifest is preserved. A network failure can leave a draft or public release: inspect it, do not blindly retry or delete. Reusing any existing release/tag is deliberately rejected.

Source inventory has relative paths and hashes, not contents or secrets. HEAD and the GitHub tag are context only: a dirty build is not attributable to an exact Git commit; GitHub's automatic source archive does not recover the hashed local source. Hash inventory is not a backup. This prototype is debug-signed and is not a production signing/release policy.

The catalog is **not separately signed**. HTTPS GitHub hosting and the Android package-signature check are current trust boundaries; a hash alone does not authenticate a publisher. Private channels, dedicated release signing, catalog signing, downgrade recovery and silent-install guarantees are not implemented here. The Android installer may require consent. No GitHub publication or physical installation is proven by offline probes.

```powershell
.\Tools\Release\Publish-GitHubApk.tests.ps1
```

API references: [GitHub releases](https://docs.github.com/en/rest/releases/releases), [release assets](https://docs.github.com/en/rest/releases/assets), [Android update requirements](https://developer.android.com/google/play/app-updates).
